# Prime Suspect UI/VFX 에셋 키트 v1

2026-10-24 제작. 수정된 인게임 기준 명세의 UI/VFX를 위한 독자 제작 SVG/CSS 자산입니다. 기존 게임 코드, 사건 데이터, manifest, 배포는 변경하지 않았습니다.

## 포함 항목

총 40개 SVG입니다. `asset-manifest.json`에 파일 경로·실제 크기·상태가 있습니다.

- 디코더 얇은 프레임 1개: 640×360. 가운데 592×312는 투명합니다.
- 인수 상태 칩 3개: 짝수 지수 / 홀수 지수 / 소수, 각 240×120. 숫자 영역은 비어 있습니다.
- 퇴실 블록 교환 스위치 3상태: idle / active / disabled, 320×88.
- 오차 복구 선택기 3상태: minus / zero / plus, 320×100.
- 모순 제시 버튼 4상태: idle / focus / pressed / disabled, 400×104.
- 방 번호 배지 24개: 2, 3, 5, 7, 11, 13, 17, 19 × default / active / attention, 96×96.
- 소인수 분리 빛줄기와 진술 파편 2개: 640×240.
- `effects.css`: 수동 시작·1회 재생 효과. 반복 점멸 및 무한 애니메이션 없음.
- `demo.html`, `demo.css`, `demo.js`: 에셋 확인용 로컬 데모. 네트워크나 계정 불필요.
- `generate_ui.py`: SVG와 자산 목록 재생성.
- `validate_ui.py`: XML·노드·번호·SVG 렌더 검사 및 미리보기 생성. Pillow와 Inkscape 필요.
- `test_demo.cjs`: Node 기반 모의 DOM 상호작용 검사. 실제 브라우저 검사를 대체하지 않습니다.

`demo.html`을 로컬 브라우저로 열면 시연 예시를 볼 수 있습니다. 이 데모는 게임이나 실제 증거 분석 기능이 아닙니다. 시연 숫자·문구는 게임 데이터에 적용되지 않습니다.

## 의미와 게임 연결 시 주의

1. 홀수 지수는 홀수 번 통과한 기록입니다. 단독으로 오류·유죄를 뜻하지 않습니다. 주목 표시는 색 외에 삼각형으로도 구분합니다.
2. 짝수 지수는 왕복과 양립하지만 무죄나 정상 데이터의 보증이 아닙니다.
3. 1009가 소수라 더 분해되지 않는 것은 정상적인 수학 결과입니다. 잠금/오류 단정 UI로 대체하지 않았습니다.
4. 교환은 Case 3 라운지 이후 퇴실 블록에 적용합니다. 전체 카드 값을 무조건 맞바꾸는 기능이 아닙니다. A/B는 슬롯 식별자이며 실제 인물 이름은 HTML에 따로 표시해야 합니다.
5. Case 4 복구는 현장 단서와 연결합니다. 송지훈은 +1, 백도현은 −1 복구입니다. 선택기 그림 자체는 판단·검증 기능이 없습니다.
6. 모순 제시 버튼에 명세에 없는 충전 게이지를 추가하지 않았습니다. 조건 미충족 시 실제 HTML button의 disabled 속성과 안내 문구를 제공해야 합니다.
7. 파편 효과는 잘못된 진술의 시각적 논파를 위한 장식입니다. 실제 증거나 카드의 파괴를 뜻하지 않습니다.
8. 지도 지형/노드 이동/특수 경로 공개는 이 키트 범위가 아닙니다. 기존 지도 자산과 공개 조건을 유지해야 합니다.

## UI 연결 권고

- SVG를 버튼 대신 직접 클릭 가능하게만 만들지 마세요. 실제 조작은 이름 있는 HTML button, 상태는 aria-pressed/disabled로 구현하고 SVG는 장식으로 취급합니다.
- 칩의 `value-slot`은 빈 영역입니다. 정확한 숫자는 HTML 텍스트나 안전하게 이스케이프한 SVG 텍스트로 넣으세요. 데모의 2², 5¹, 1009는 시연 예시입니다.
- 화면 폭이 작아도 터치 영역은 최소 44 CSS px, 글자는 읽기 쉬운 크기를 유지합니다. 숫자가 길면 줄바꿈/가로 공간을 별도 설계해야 합니다.
- 한글 SVG는 Noto Sans CJK KR → Malgun Gothic → sans-serif 순으로 대체됩니다. 외부 폰트를 다운로드하지 않습니다. 폰트에 따른 실제 기기 표시 차이를 검수해야 합니다.
- VFX를 CSS로 움직일 때 SVG를 DOM에 인라인으로 넣고 `.ps-vfx`를 붙입니다. 검증된 게임 이벤트에서 `.ps-play`를 한 번 붙였다가 종료 시 제거합니다. img 태그 내부는 외부 CSS로 조작할 수 없습니다.
- 여러 VFX를 동시에 인라인으로 복사하면 title/desc/그룹 id가 충돌하지 않도록 인스턴스별 접두어를 붙이세요. 데모는 각 효과 1개만 사용합니다.
- `prefers-reduced-motion: reduce`에서는 효과를 숨기고 상태 메시지를 제공합니다. 빠른 점멸·반복 효과는 넣지 않습니다.
- 게임의 성공/실패 판정, 이벤트와 효과음 연결, 취소/화면 이동 시 정리, 실제 접근성·실기기 터치 검수는 후속 통합 범위입니다.

## 검증 결과와 한계

- 40개 SVG XML 파싱, viewBox/크기/고유 ID/접근성 제목·설명 검사 통과.
- 24개 방 배지의 숫자 및 3종 칩의 빈 값 영역 확인.
- 모든 SVG를 Inkscape로 PNG 렌더링하고 전체 미리보기의 겹침·가독성을 육안 확인.
- 프레임 중앙 픽셀 투명도 확인.
- JS 문법 검사, 모의 DOM 8개 시나리오 통과: 교환 반복, 선택기 반복, VFX 중복 입력 차단, 취소, 종료, reduced motion, 설정 변경, 페이지 이탈 정리.
- 실제 Chromium 실행은 환경의 `socket() failed: Operation not permitted`로 차단되었습니다. 보안 우회 없이 중단했으며 실제 브라우저 레이아웃/애니메이션, 모바일 터치, 화면 읽기 도구 테스트는 미실시입니다.
- VFX는 자산·시연 수준이며 게임 연출에 연결된 완성 기능으로 표시하지 않습니다.
